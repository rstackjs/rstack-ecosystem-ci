# Ecosystem CI website

The website uses TanStack Start SSR on Cloudflare Workers, built with Rsbuild and
`rsbuild-plugin-cloudflare` through `rstack.config.ts` and the `rs` commands.
TanStack Start renders the page shell and loading state on the server. After
hydration, the browser fetches the seven stack JSON files from
`https://ecosystem-ci-data.rstack.rs`. History is not embedded in the HTML.
Stack and suite changes reuse this snapshot; reload the page to fetch the latest
history.

- `pnpm dev`: start the development server; data is fetched by the browser.
- `pnpm build`: build the Worker and static assets without fetching history.
- `pnpm preview`: preview the production build in workerd.
- `pnpm deploy:prebuilt`: deploy the existing `.cloudflare/output` build.
- `pnpm deploy:preview`: upload an existing preview build as a Worker Preview.

Run these commands from `website/`, or run `pnpm build:website` from the repository
root. Route and Worker binding types are generated by `rs dev` and `rs build`.

## Cloudflare Workers Builds

Connect this repository to the `rstack-ecosystem-ci` Worker using these
[Workers Builds settings](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/):

| Setting           | Value                                                |
| ----------------- | ---------------------------------------------------- |
| Production branch | `main`                                               |
| Root directory    | Repository root (`/`)                                |
| Build command     | `pnpm build:website`                                 |
| Deploy command    | `pnpm --filter ecosystem-ci-website deploy:prebuilt` |
| Preview command   | `pnpm --filter ecosystem-ci-website deploy:preview`  |

Use the Node.js version in `.nvmrc` and pnpm version in `package.json`.
Cloudflare builds and deploys on changes to `main`.

### PR previews

After merging this configuration, set the Preview command above and enable
**Builds for Preview branches** under **Settings > Builds > Branch control**.
Enable Preview URLs on the Worker's `workers.dev` domain if they are disabled.
Workers Builds creates previews for non-production branches and posts their URLs
to associated pull requests through its GitHub integration.

The shared build command uses `WORKERS_CI_BRANCH` to set
`CLOUDFLARE_PREVIEW_BUILD=true` on branches other than `main` in Workers Builds.
This lets `rsbuild-plugin-cloudflare` generate the preview Build Output required
by `cf previews deploy --prebuilt`. Builds for `main` produce production output.
Keep the production branch setting and the comparison in `rstack.config.ts` in sync.
The preview name defaults to the branch name, so subsequent pushes update that
branch's preview. The pinned `cf` version supports reporting Preview URLs to
Workers Builds; no GitHub Actions deployment workflow or new repository secret
is needed.

Before enabling preview branches, configure
[Build watch paths](https://developers.cloudflare.com/workers/ci-cd/builds/build-watch-paths/)
with these include paths (one per entry), replacing the default `*`:

```text
website/*
package.json
pnpm-lock.yaml
pnpm-workspace.yaml
.nvmrc
patches/*
rstack.config.ts
tsconfig.json
```

This skips routine `data` branch JSON updates and unrelated CI suite changes.
Cloudflare bypasses path filters for empty pushes, pushes with 3,000+ changed files,
or 20+ commits; these filters are not a branch exclusion rule.

Previews use the same public history endpoint as production. They need no extra
runtime bindings or secrets. For a manual preview build, run
`CLOUDFLARE_PREVIEW_BUILD=true pnpm build` from `website/`, then
`pnpm deploy:preview` with Cloudflare authentication configured.

## Data deployment

Cloudflare Pages publishes the `data` branch of this repository at
`https://ecosystem-ci-data.rstack.rs`. The Pages project uses `exit 0` as its build
command, `.` as its output directory, and automatic production deployments for
`data` only. Each stack is available at `/<stack>.json`.

History updates deploy independently of the website. The Worker no longer needs
scheduled rebuilds or a Deploy Hook to refresh data. After this change is deployed,
the `CLOUDFLARE_WORKERS_DEPLOY_HOOK_URL` secret and its Cloudflare Deploy Hook can
be removed.

## Temporary compatibility patch

The pnpm patch for `@tanstack/start-plugin-core` fixes missing development CSS
in workerd ([TanStack/router#8886](https://github.com/TanStack/router/issues/8886)).
Remove it after upgrading to an upstream-fixed version and verifying CSS in
development and production preview. Rstack 0.9 / Rsbuild 2.3 also includes the
required SSR define fix for web-worker targets.
